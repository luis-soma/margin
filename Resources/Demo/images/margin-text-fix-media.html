What “CI” is: I think the “Cl” you saw is CI, short for continuous integration. It’s a GitHub service that builds and checks the app in the cloud whenever I push. For Margin it rents a Mac each time and:

  • builds the app,
  • runs about 130 automated tests,
  • makes one real call each to Gemini and OpenAI to confirm the keys work,
  • compiles the app icon file for Macs that can’t do that themselves.

Do we need it? Not to use Margin. Update Margin builds the app on each person’s Mac, which is why your friends could pull without it. What you lose without CI:

  • No safety check: I can’t confirm a change builds before you get it. A mistake would first show up as a failed Update Margin on your Mac, though your current version keeps working.
  • No icon refresh: the icon file only needs recompiling if we change the icon again.

Why the limit hit: builds on GitHub’s Macs are expensive for private repos. GitHub counts each Mac minute as ten regular minutes. I’ve also been triggering two builds per change, one per branch.

What I’d do: run CI only for main and only when app code changes, which roughly halves the usage. Then raise the spending limit a little before the deadline if you want the checks back. Or we skip CI until Monday and I’m extra careful. Which do you prefer?
